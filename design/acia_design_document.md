# AI Command Assistant (ACliA) 設計書

## 1. システム概要

### 1.1 目的

AI Command Assistant (ACliA) は、コマンドラインインターフェース（CLI）操作を支援するツールであり、自然言語による指示から適切なコマンドを提案します。このツールは特に CLI 初心者や複雑なコマンド操作に時間を費やしているユーザーの生産性向上を目指します。

### 1.2 システムの位置づけ

本システムは、ユーザーとコマンドラインの間に位置し、ユーザーが自然言語で表現した操作意図を解釈し、適切なコマンドに変換する橋渡し的役割を果たします。既存のヘルプコマンドやマニュアルと異なり、タスク指向の自然言語入力からコマンドを生成する点が特徴です。

## 2. システムアーキテクチャ

### 2.1 全体構成

```
+------------------+    +----------------+    +---------------+
|                  |    |                |    |               |
| ユーザーインターフェース | -> | コア処理エンジン | -> | コマンド実行環境 |
|                  |    |                |    |               |
+------------------+    +----------------+    +---------------+
        ^                      ^                     |
        |                      |                     |
        v                      v                     v
+------------------+    +----------------+    +---------------+
|                  |    |                |    |               |
| 設定・履歴管理     | <- |  LLMサービス   | <- | 実行結果フィードバック|
|                  |    |                |    |               |
+------------------+    +----------------+    +---------------+
```

### 2.2 主要コンポーネント

| コンポーネント           | 役割                                                   | 実装方針                           |
| ------------------------ | ------------------------------------------------------ | ---------------------------------- |
| ユーザーインターフェース | 自然言語入力の受付、コマンド候補の提示、対話的絞り込み | CLI アプリケーション (Rust + clap) |
| コア処理エンジン         | 自然言語解析、コマンド生成ロジック、安全性チェック     | Rust コアロジック                  |
| LLM サービス連携         | 自然言語からコマンドへの変換処理                       | OpenAI API 等の外部サービス連携    |
| コマンド実行環境         | 生成したコマンドの実行と結果取得                       | シェル連携 (std::process)          |
| 設定・履歴管理           | ユーザー設定の保存、過去の成功コマンドの記録           | ローカルファイル (TOML/JSON)       |

## 3. 機能詳細設計

### 3.1 自然言語入力処理 (FR-001)

#### 3.1.1 入力方式

- CLI パラメータとして指定: `acia "カレントディレクトリのテキストファイルを検索"`
- 対話モード: `acia` を実行し、プロンプトに入力

#### 3.1.2 入力前処理

- 不要な空白や特殊文字の正規化
- 言語検出（日本語/英語等）と LLM プロンプト最適化

### 3.2 コマンド生成・提案 (FR-002)

#### 3.2.1 LLM プロンプト設計

- システムプロンプト: コマンド生成タスクの説明、期待される出力形式
- ユーザープロンプト: 正規化された自然言語入力
- 出力形式: JSON 形式（コマンド文字列、説明、危険度等を含む）

#### 3.2.2 複数候補の処理

- 最大 3 件の候補を生成
- 候補ごとに説明と用途の違いを提示

### 3.3 コマンド説明表示 (FR-003)

#### 3.3.1 説明コンポーネント

- コマンドの全体的な目的
- 主要オプションの説明
- 想定される実行結果
- 関連コマンドへの参照

#### 3.3.2 表示形式

```
COMMAND: find . -name "*.txt" | xargs wc -l

PURPOSE: カレントディレクトリ以下のテキストファイルを検索し、各ファイルの行数を表示します

OPTIONS:
  - find . -name "*.txt": カレントディレクトリ(.)から.txt拡張子のファイルを検索
  - xargs wc -l: 検索結果の各ファイルに対してwc -lコマンド（行数カウント）を実行

RELATED: grep, ls, cat
```

### 3.4 対話的絞り込み (FR-004)

#### 3.4.1 曖昧さの検出

- LLM による入力の曖昧性スコアリング
- 追加情報が必要な項目のリスト生成

#### 3.4.2 質問生成と回答処理

- 優先度順に質問を提示
- 回答をコンテキストに追加し、再度コマンド生成を実行

### 3.5 危険コマンド検出・警告 (FR-005, FR-006)

#### 3.5.1 危険度評価基準

- レベル 1: 通常の操作（ls, cat 等）
- レベル 2: 注意が必要な操作（chmod, mv 等）
- レベル 3: データ消失リスクがある操作（rm, dd 等）

#### 3.5.2 警告表示と代替案

- レベル 2: 黄色で警告表示、リスク説明
- レベル 3: 赤色で警告表示、リスク説明と安全な代替案提示、確認要求

### 3.6 ユーザーインターフェース設計

#### 3.6.1 候補選択インターフェース (FR-007)

- 番号選択方式
- 矢印キーによる選択（TUI 機能が利用可能な場合）
- 詳細表示とコマンド実行の 2 段階選択

#### 3.6.2 コマンドコピー・実行機能 (FR-008, FR-009)

- コピー機能: クリップボードへの自動コピーとコピー確認表示
- 実行機能: 実行前の最終確認と実行結果の表示

### 3.7 将来拡張機能

#### 3.7.1 履歴管理 (FR-010)

- 成功コマンドの自動記録
- 頻度ベースの推奨コマンド表示
- エクスポート・インポート機能

#### 3.7.2 設定機能 (FR-011)

- 設定ファイル形式: ~/.config/acia/config.toml
- 主要設定項目: API キー、好みのコマンド置換ルール、警告レベル

## 4. 技術的実装詳細

### 4.1 開発言語・フレームワーク

- 主言語: Rust
- UI ライブラリ: clap (CLI 引数処理), crossterm/tui-rs (対話モード)
- 外部 API: OpenAI API (または他の LLM サービス)

### 4.2 主要モジュール構成

```
src/
  ├── main.rs            # エントリポイント
  ├── cli/               # CLIインターフェース
  │   ├── mod.rs
  │   ├── args.rs        # 引数処理
  │   └── interactive.rs # 対話モード
  ├── core/              # コア処理ロジック
  │   ├── mod.rs
  │   ├── engine.rs      # メイン処理エンジン
  │   ├── command.rs     # コマンドオブジェクト
  │   └── safety.rs      # 安全性チェック
  ├── llm/               # LLM連携
  │   ├── mod.rs
  │   ├── client.rs      # APIクライアント
  │   └── prompt.rs      # プロンプト管理
  ├── config/            # 設定管理
  │   ├── mod.rs
  │   └── settings.rs    # 設定読み書き
  └── utils/             # ユーティリティ
      ├── mod.rs
      ├── clipboard.rs   # クリップボード連携
      └── shell.rs       # シェル実行
```

### 4.3 データフロー

1. ユーザー入力受付 (cli::args または cli::interactive)
2. 入力の正規化と初期解析 (core::engine)
3. LLM へのリクエスト生成と送信 (llm::client)
4. LLM 応答の解析とコマンドオブジェクト生成 (core::command)
5. 安全性チェックと警告/代替案生成 (core::safety)
6. 結果の表示とユーザー操作受付 (cli::interactive)
7. 選択されたアクション実行 (utils::clipboard または utils::shell)

### 4.4 エラーハンドリング

| エラー種別         | 対応方針                                                    |
| ------------------ | ----------------------------------------------------------- |
| LLM API 接続エラー | リトライ+フォールバック（ローカルの簡易パターンマッチング） |
| コマンド実行エラー | エラーコードと出力の解析、解決策の提案                      |
| 入力解析エラー     | 明確なエラーメッセージと入力例の提示                        |

## 5. セキュリティ考慮事項

### 5.1 潜在的リスク

- 危険なコマンドの実行
- ユーザーデータの外部送信
- API キーの漏洩

### 5.2 対策

- 3 段階の安全性チェック（LLM 内、コア処理内、実行前）
- API キーの安全な保存（OS のキーチェーン/資格情報マネージャ利用）
- 送信データの最小化と匿名化
- オフラインモードのサポート（将来拡張）

## 9. API インターフェース仕様

### 9.1 LLM API リクエスト形式

```json
{
  "model": "gpt-4",
  "messages": [
    {
      "role": "system",
      "content": "あなたはコマンドライン操作の専門家です。自然言語の指示からシェルコマンドを生成してください。..."
    },
    {
      "role": "user",
      "content": "<ユーザーの入力>"
    }
  ],
  "temperature": 0.2,
  "response_format": { "type": "json_object" }
}
```

### 9.2 LLM API 応答形式

```json
{
  "commands": [
    {
      "command": "find . -name \"*.txt\" | xargs wc -l",
      "description": "カレントディレクトリのテキストファイルを検索して行数を表示します",
      "safety_level": 1,
      "explanation": {
        "purpose": "テキストファイルの検索と行数カウント",
        "components": [
          {
            "part": "find . -name \"*.txt\"",
            "explanation": "カレントディレクトリから.txt拡張子のファイルを検索"
          },
          {
            "part": "xargs wc -l",
            "explanation": "各ファイルの行数をカウント"
          }
        ]
      }
    }
  ],
  "is_ambiguous": false,
  "additional_questions": []
}
```

## 10. ユーザビリティ設計

### 10.1 ターゲットユーザーペルソナ

- 「CLI 初心者の A さん」: プログラミング学習中の大学生
- 「効率化を求める B さん」: 日常的に CLI を使用するエンジニア

### 10.2 ユーザー体験フロー

4. ユーザーによるアクション選択（コピー/実行/詳細表示）
